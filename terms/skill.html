Skill / Skills / Slash Command

技能

把一套做事的規矩存成一份檔案，用得到的時候整份塞進去。存的不是提示詞，是流程。

定義

技能是一份寫著「什麼時候該用、用了照什麼流程跑」的檔案。需要的時候被整份塞進模型眼前，不需要的時候不佔位置。

一份技能檔通常分兩塊：

描述
什麼時候該叫出這一份。平常只有這一行被看到
內容
完整的工作流程、輸出格式、硬性規則、檢查清單

這個兩層結構是重點，不是版面。模型一次看得進去的字有限，所以平常只讓它看見每一份技能的那一行描述；判斷這次用得到，才把整份載進來。

它跟系統提示詞的差別就在這裡：系統提示詞是每一次都塞的一整包，技能是按情境才塞的一份份。

別把它想成「一段存起來的提示詞」

存一段話下次重貼，那只是罐頭訊息。技能存的是流程與判準——第幾步做什麼、輸出長什麼樣、哪些情況直接退回。會被重複使用的是那套判準，不是那段措辭。

為何會出現

因為交代一次是沒有用的。

一次對話裡把規矩講清楚，那套規矩只活在這個視窗裡。關掉、換一個人、換一個月，全部重來，而且每次重講的版本都不太一樣——於是同一件事的產出風格漂來漂去，沒有人說得出「正確的做法」到底是哪一版。

寫成檔案就解決了這件事：規矩有了一個放的地方，可以改、可以版控、可以交接。這條路跟先撈再答是同一個動作的兩半——檢索端自動撈它該看的知識，技能是你指定它該遵守的規矩，兩邊都是在回答之前把東西塞到它眼前。

但這個做法不是一直都划算。它要等三件事同時成立才成立，而三件事都是最近幾年才到位的：

要有什麼 沒有的時候會怎樣
塞得下——上下文視窗要夠大 一份完整的流程檔就吃掉全部額度，你的問題和資料放不進去
塞了會照做——後訓練把「遵循指示」練進去 它把那份流程當成一段文章讀完，然後接著寫下去，不是照著跑
會自己挑該用哪一份 每次都要你指名「用第七號檔案」，那跟自己貼一段字沒有差別

所以技能的技術含量幾乎是零——它就是一個文字檔。值錢的不是這個檔案，是那三道閘門剛好都開了。

金融背景怎麼理解

它最接近的東西是作業辦法，但寫法不一樣，而且差別很致命。

作業辦法是寫給人看的，人會自己權衡例外，所以裡面充滿「原則上」「必要時」「得視情況」——那是刻意留的裁量空間。技能是寫給不會權衡的東西看的：留了模糊空間，它就會自己判斷，然後在你最不希望的那一次放行。

所以同一件事，寫給人的版本和寫給它的版本要分開寫。硬條件寫成硬條件：不是「儘量落在期間內」，是「不在期間內就整筆刪除」。

比較像交接手冊，不像教育訓練

教育訓練是講給在場的人聽，人走了就沒了。交接手冊是留在抽屜裡的，接手的人照著做就跑得出同一份東西。導入 AI 工具能不能交接，看的就是這份檔案存不存在。

驗收委外或 PoC 的時候，這一條可以直接寫進交付項目：除了成果，要不要求對方交出那份規矩檔。沒有它，那套做法留在原本那個人的腦子裡，人走了就得從頭試一次。

Tools vs Skills vs Plugins

三個常被混用的詞，都是「給 AI 額外能力」，但層次不同

Tools（工具）
是什麼
AI 能呼叫的具體功能，如「搜尋網路」、「查資料庫」、「計算數值」
優勢
AI 原生概念，是 Agent 執行動作的最小單元
劣勢
單個工具功能有限，需要組合才能完成複雜任務
適合
描述 AI 能做的單一具體動作（搜尋、計算、傳送）
Skills（技能）
是什麼
預先定義好的 AI 行為模組，包含提示詞邏輯與工具組合
優勢
可重複使用、標準化、不需每次重新描述任務
劣勢
需要前期設計與維護
適合
封裝常用的複合型 AI 任務（如「每日新聞摘要技能」）
Plugins（擴充套件）
是什麼
平台層面的功能擴充，讓使用者在 AI 介面中安裝額外服務
優勢
使用者可自行安裝，不需開發者介入
劣勢
平台綁定，標準不一致
適合
讓使用者自行選擇需要哪些 AI 附加功能
核心差異

由小到大：Tools 是一個動作 → Skills 是一套做事方法 → Plugins 是一個功能套件。設計 AI 系統時，先定義 Tools，再把常用組合封裝成 Skills，最後以 Plugins 形式讓使用者選用。

金融業應用情境

查帳務 = Tool；每日風險評估流程 = Skill；Bloomberg 資料連結 = Plugin

提示詞 vs 系統提示詞 vs Skill

三個東西送進模型的都是文字，差在誰寫的、什麼時候進去、有沒有一個存放的地方

提示詞（Prompt）
是什麼
你這一次打進對話框的那段字。內容、長短、格式都由你當下決定，送出去就跟著這次的對話一起結束
優勢
零成本、零設定，想到什麼調什麼；探索階段最快
劣勢
活在這個視窗裡。關掉就沒了，換一個人打就是另一個版本，說不出「正確的做法」是哪一版
適合
一次性的問題、還在試水溫的階段、每次條件都不一樣的任務
系統提示詞（System Prompt）
是什麼
由系統方事先寫死、接在使用者每一句話前面的那段字。使用者通常看不到它，但每一輪都在
優勢
每一次自動生效，不必使用者記得；同一顆模型換一段系統提示詞，對外就是不同的服務
劣勢
一整包、不分情境，寫太多會排擠掉真正要處理的內容；不在版控裡，改一行不用上線卻能整個換掉行為
適合
角色、語氣、輸出格式、絕對不准碰的題目——這些每一次都成立的事
Skill（技能）
是什麼
一份寫著「什麼時候該用、用了照什麼流程跑」的檔案。平常只有那一行描述被看到，判斷這次用得到才整份載入
優勢
按情境才佔位置，所以可以寫得很長很細；是檔案，可以改、可以版控、可以交接給下一個人
劣勢
要先寫；描述寫得不夠具體它就不會在對的時候叫出來；欄位格式各家工具不一樣，會隨版本改
適合
會重複跑的產出——固定流程、固定格式、有硬性規則、而且要換人也跑得出同一份的那種
核心差異

提示詞是「這一次」，系統提示詞是「每一次」，Skill 是「需要的那幾次」。三者送進模型的都是文字，真正的分野在有沒有一個存放的地方：前兩者改了沒有紀錄、交接不了，Skill 是一份檔案，所以它能變成資產。另外只有 Skill 是由模型自己讀描述決定要不要載入的——這也是它不叫「提示詞範本」而叫「技能」的原因。

金融業應用情境

提示詞：臨時要一份會議紀要摘要。系統提示詞：所有對外文件一律繁體中文、不得出現客戶姓名。Skill：週報產製、合約比對這類格式固定的活——流程、輸出格式、硬性規則寫成一份檔案，驗收委外或 PoC 的時候把這份檔案列進交付項目。
